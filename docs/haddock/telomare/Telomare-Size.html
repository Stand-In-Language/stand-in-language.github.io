Telomare.Size

Description

The sizing pass: telomare's totality checker. sizeTermM abstractly interprets the program over a symbolic input, unbounded but where a refinement check bounds a value the computation after it reads (narrowChecked), and infers, per unsized recursion site, an iteration count that holds for every input - then bakes those counts into the term as church towers. A program that cannot be sized does not compile (SizingFailure).

refinementGate :: Int -> AbortOrigin -> InputSizingExpr -> InputSizingExpr -> InputSizingExpr Source #

if r then c else abort (1, c) over an evaluated check result r and value c: what a refinement check reduces to once its check function has run.

An undecided r leaves a barrier-wrapped gate switch with r itself as the scrutinee. Gating on r the usual way would push the gate into r's own residual gates, copying c onto every path that passes, and nested checks would multiply the copies. Left whole, c appears once, and whatever is done to the guarded value later goes into just its two branches, one of which stays an abort.

refinementCheckStep :: Int -> InputSizingExprF InputSizingExpr -> InputSizingExpr Source #

Evaluates a refinement check function against symbolic input, leaving input-dependent gates as barrier-wrapped residuals for extractInputRestrictions.

A refinement nested inside the check (e.g. a check calling a Prelude function whose arguments are refined) is evaluated in place: a decided check reduces to its value or an abort, an undecided one to a gate switch with an abort branch, so its restrictions apply only on the gate paths where the nested check actually runs.

unfoldRecursion :: Int -> UnsizedRecursionF InputSizingExpr -> InputSizingExpr Source #

One step of an unsized recursion inside a refinement check (refinementCheckStep), unfolded as sizing unfolds it (unsizedStepM''), so a check counting a constant (Num 2, Vector 9, d2c 57 left x) restricts the input it reads. Where the recursion's test reads the input instead, or it runs past the fuel (the sizing budget, maxSizingSize, as for sizing itself), its result is unknown.

sizeTermM :: SizingSettings -> UnsizedExpr -> Either SizingFailure (SizedRecursion, CompiledExpr) Source #

Size every recursion site, returning the iteration counts alongside the compiled term. The counts are the numbers the compiler already relies on to claim the program is total; handing them back costs nothing, and re-running this pass to recover them would cost minutes.

The failure carries no location — UnsizedExpr has none. Callers holding the Term3 fill it in (see locateSizingFailure).

narrowChecked :: Int -> AbortOrigin -> UnsizedExpr -> UnsizedExpr -> Maybe UnsizedExpr Source #

The value a refinement check passes on, narrowed to what passing it requires. The check runs over the value symbolically (refinementCheckStep), and each input position the value holds is replaced by the shape the check's restrictions allow (narrowTo). Sizing goes on with the narrowed value, so a check bounds exactly the computation its value flows into: only the inputs that pass it reach there, since the others abort at it. Nothing when there is nothing to narrow.

toCheckValue :: UnsizedExpr -> InputSizingExpr Source #

A value of the sizing run, as the check evaluator reads it. It has no superpositions: one is an unknown there. A bounded input position reads as the position, which only loses what bounds it.

narrowTo :: InputRestrictions -> UnsizedExpr -> UnsizedExpr Source #

Each input position in a value, narrowed to what the restrictions allow it: a pair where a pair is required at or below it, and otherwise the position under the zeros required of it (boundedInput), which a bounded position adds to its own.

analyzeChecks :: Int -> UnsizedExpr -> Set Integer -> CompiledExpr -> Maybe CheckAnalysis Source #

Run a sized main once over a symbolic input, through exact superpositions that keep each path apart (exactSuperStepM; sized chains make it finite), recording every run of a refinement check that may fail. Nothing when that would take more than the budget of evaluation steps.

Running every check with every value that can reach it, the run sees where each check fails: a check's abort carries a message that is Zero where it passes and the failing value under a pair where it fails (refinementCheckB), so an abort that fires with something other than Zero on some path (mayBeNonZero) is a check that may fail there.

The input covers only what the zeros admit. For an answer to hold of every run, an input they rule out must never reach main, or there must be none. What the abstract run cannot follow (data applied as a function, a stuck projection) becomes an unknown value, and a check reaching one may fail. A fired abort is recorded and then forgotten: every aborted value is the same one, so that runs differing only in which check stopped them merge.

runTree :: UnsizedExpr -> CheckFire -> CheckTree Source #

One run of a check that depends on the input alone, as a decision: its result's own decisions over the input, down to where it fails, and there what main's result does. A user if or case computes both its branches, so a check in one runs whichever is taken, and the condition under which its abort matters is in main's result: the path is split on the result's own superpositions until it is decided, or the splits run out (demandSplits).

Where the run surely aborts, the failure is decided before main, unless it can happen on the input-less first call, which runs without the prologue (the path does not say the input is a pair), or the path has come to depend on the state (main's input is (input, state): the input is under position 1; position 0 says whether there is any). Failing before main then aborts exactly the runs main would have aborted. Where the run aborts in no case, the failure is never seen.

onInput :: Integer -> Bool Source #

Whether an input position is in the input, not the state: main's input is (input, state), so under 1, or 0 itself, whether there is any.

checkVerdicts :: CheckAnalysis -> Map AbortOrigin CheckVerdict Source #

Where each check that may fail goes. A check whose every run depends on the input alone (fireReads, onInput) is decided run by run (runTree). It stays in main if any part of any run is undecided, and then entirely: deciding its other failures before main as well would only make them twice. Any other check stays in main.

inputPrologue :: Map AbortOrigin CheckVerdict -> Maybe CompiledExpr Source #

main's input prologue: a function run on main's input before main, giving Zero when every hoisted check passes and, when one does not, the abort of the first in the order they were written. Nothing when no check is hoisted. The first call of main, made before there is any input, runs without it (funWrapWith).

Each run of a check decided before main becomes its tree (runTree) as gates on input positions, under gates testing the path that reached it: Zero where it passes, its abort where it fails. Of what the path knows, only the deepest of its pairs and the shallowest of its Zeros are tested, since the rest follows. The verdicts are chained through gates, which an aborted verdict ends.

An input position as code whose env is (input, _): position 0 is the input, and 2n + 1 and 2n + 2 are n's left and right.

renderSizingCertificate :: SizingReport -> String Source #

Every recursion site in the program, where it is, and how many times it can iterate. The counts hold for every input: the sizing pass finds them by running the program over a symbolic input, and takes the worst case across the paths it explores.

Nothing here is a new claim. These are the very numbers the compiler bakes into the program to make it total; a program that does not size does not compile at all.
