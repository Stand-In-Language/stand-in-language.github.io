data CompiledProgram Source #

The compilation product: the sized program together with everything compilation proved about it. The EAL fields are about the code that will actually run — distinct from the pre-sizing certifyMain gate, whose verdict is about the recursion scaffolding as well — and are derived from a certificate of the unsized program that holds for every size (certifiedProgramFrom), or inferred over the sized program when that certificate does not cover it. They are lazy, so a run on the reference evaluator never pays for them; writing an artifact or admitting the IC runtime forces them once, and from then on they travel with the program.

    Per-hash guidance for every body (all of them, when the program certified), post-sizing — the map runtime strategies draw on.

  • cpVerdict :: Either String EALResult

    The post-sizing whole-program verdict. The reference evaluator ignores it; IC admission (programPlan) is exactly this field. A refusal is carried rendered: it is for showing, and keeping it structured would mean serializing blame chains into artifacts.

Package a sized program with its post-sizing EAL product, derived from the size-independent certificate of the program it was sized from (inferEALFaithful) when that certifies — a derivation is a relabelling, where inferring the sized program again costs most of a compile — and inferred over the sized program otherwise.

programPlan :: CompiledProgram -> Either String ICPlan Source #

IC admission, read off the carried verdict: the plan when the program certified post-sizing, the rendered refusal when it did not. Unlike admitIC this runs no inference — compilation already did — so admitting an artifact is a field access.

Parse and compile a module set into the full compilation product. Every problem comes back as text a user can act on rather than as an exception, so callers decide how to report it.

Each module is parsed under its own name, so the locations in diagnostics can say which file a term came from.
